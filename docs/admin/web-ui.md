# Web UI 指南

内置的 Web UI 提供了管理 ToolRegistry 的可视化界面。

## 界面概览

面板是一个控制台：顶部固定标题栏，左侧是分区导轨，右侧是所选分区的内容。

- **工具**：全部已注册工具，按命名空间分组，带概览条、过滤器与按工具/按命名空间的控制
- **来源**：工具来自哪里，以及 **添加来源** —— 连接 OpenAPI、MCP 或 Python 来源并挑选要保留的工具
- **日志**：执行历史，支持过滤
- **权限**：每个工具的权限评估结果
- **Schema**：发布给模型的 schema，以及 discover 索引
- **状态**：导出/导入与注册表级设置

不再有独立的命名空间页面：命名空间只是工具的分组，因此留在工具列表里。每个分组头
带有批量控制（整组启用/禁用、整组 THINK 与 DEFER），点击名称可折叠或展开该组，
而概览里的命名空间计数会折叠所有分组，让列表呈现为命名空间汇总。

点击导轨底部的按钮可将其折叠为图标（选择会被记住）；宽度小于 900px 时，
导轨变为由标题栏菜单按钮打开的抽屉。标题栏固定在顶部，并与导轨使用同一底色，
两者看上去像包裹内容的同一个框架。

「工具」分区顶部的概览卡片即为入口：总数打开未过滤的列表，已启用/已禁用打开
按该状态过滤的列表，命名空间数量则打开命名空间面板。

## Schema

Schema 分区展示发布给模型的 schema。格式选择器使用 llm-rosetta 的规范、中立名称：
`chat_completions`、`open_responses`、`messages`、`google_generate`、
`google_interactions` 与 `rosetta_ir`；`GET /api/schema?format=…` 同时接受这些名称与
旧写法（`openai-chat`、`anthropic` 等），旧写法继续有效。

## 分区之间互相跳转

描述工具来源的四个分区已经连通，任何一个数字都是进入对应列表的入口：

| 起点 | 点击 | 到达 |
|---|---|---|
| 概览 | 总数 / 已启用 / 已禁用 | 工具列表，按状态过滤 |
| 概览 | 命名空间 | 工具列表，所有分组折叠——命名空间汇总 |
| 概览 | 分组内的命名空间计数 | 折叠或展开该分组 |
| 工具 | 来源徽章 | 来源面板，按该来源类型过滤 |
| 来源 | 命名空间名称 | 工具列表，按命名空间过滤 |
| 来源 | 「查看 N 个工具」 | 工具列表，按来源与命名空间过滤 |
| 来源 | 「从此来源继续注册」 | 添加来源表单，预填类型、地址与命名空间 |
| 添加来源 | 预览中的工具名 | 该工具的详情弹窗 |
| 添加来源 | 注册后的「查看已注册工具」 | 工具列表，按刚使用的命名空间过滤 |

## 主题

面板内置两套配色 —— **Paper**（暖色中性，黄铜强调）和 **Slate**（冷色中性，蓝色强调），
每套都有浅色与深色模式。在标题栏选择配色，并用旁边的按钮切换深浅色；两者都保存在
`localStorage` 中并在首次绘制前应用，因此刷新不会闪现默认值。

外观被拆成两层，且这一边界由测试保证，而不是依赖评审。**配色（scheme）**只声明取值：
`css/base.css` 为每种配色与模式的组合提供一个区块，区块内只允许自定义属性。
**组件**——`css/components.css` 与标记——决定这些取值落在何处：盒模型、布局、指针行为。
任何超出配色与模式范围的选择器（例如 `[data-scheme="slate"] .card`）都会被
`tests/test_admin_theme.py` 拒绝；某个配色声明了而另一个配色缺失的 token 同样会被拒绝。

新增配色需要：一个结构区块、每个模式一个区块、在 `js/core/theme.js` 的 `SCHEMES`
中加入名称、在标题栏下拉中加入选项，并在两份字典中加入标签。契约测试会自动覆盖它。

### 添加来源

「来源」分区中的 **添加来源** 连接来源，并在**注册任何工具之前**列出它可以提供的工具：

1. 选择类型 —— **OpenAPI**（规范地址或路径）、**MCP**（服务器地址，或 stdio 命令）
   或 **Python**（模块，可选地限定到某个类或函数）。
2. 可选地填写命名空间；预览中的名称已经包含它，因此勾选的就是最终注册的。
3. OpenAPI 与 MCP 来源可设置 **认证**：Bearer Token、Basic 账号密码，或按
   `Name: value` 每行一个填写的额外请求头。此处填写的 `Authorization` 请求头优先于
   上方的认证字段，因此面板未建模的认证方式也能发送。凭据只用于预览与注册，不会写入注册表。
4. 点击 **预览工具**，列出该来源提供的全部工具，并标记已注册的项；
   列表支持 **全选**、**全不选**、**反选** 与 **刷新**。
5. 勾选要保留的工具，点击 **注册所选**。只有被勾选的名称会被提交，
   来源无法注册任何未经选择的工具。

无法连接服务器、无法导入模块、规范缺少 `servers[]` 等错误会在面板中报告，
而不是被静默注册。需要 Token 却未提供时服务器返回的错误内容为空，面板会明确提示
并指向认证字段。

部分模型 API 不接受某些工具名：OpenAI 与 Anthropic 只允许 `[A-Za-z0-9_-]` 且不超过
64 个字符，Gemini 另外允许点号。因此 MCP 服务器提供的 `fs/file_search_glob` 这类名称
会被注册表如实保存，但会让某些 provider 的 schema 不合法。预览会列出这些名称；
已注册工具若名称不符合严格字符集，会在工具表中显示 `!` 标记。

## 工具管理

- 点击工具旁边的开关来启用/禁用
- 禁用的工具会显示原因（如果提供）
- 点击工具名称可在详情弹窗中查看完整 schema、元数据和权限信息
- 使用搜索栏按名称搜索工具
- 按 `ToolTag` 标签过滤工具（如 READ_ONLY、DESTRUCTIVE、NETWORK）

### 元数据标签

每个工具行显示元数据标签以便快速识别：

- **ToolTag 标签**（彩色编码）：READ_ONLY、DESTRUCTIVE、NETWORK、FILE_SYSTEM、SLOW、PRIVILEGED
- **位置标签**：`local` 或 `remote`（非 `any` 时显示）
- **`async`**：表示该工具为异步工具

### 运行时元数据控制

`think_augment` 和 `defer` 属性可直接从 UI 进行运行时切换：

- **工具级复选框**：每个工具行有独立的 Think 和 Defer 列，各带一个复选框
- **命名空间级复选框**：命名空间标题行包含复选框，应用于命名空间内的所有工具
- Think 复选框控制生成的 schema 是否暴露保留的 `toolcall_reason` 理由字段
- 更改立即生效，无需重启服务
- 仅 `think_augment` 和 `defer` 可在运行时修改（其他元数据字段为只读，确保安全）

### 工具详情弹窗

点击工具名称可打开详情弹窗，包含三个区块：

- **Schema**：工具参数的完整 JSON Schema
- **Metadata**：所有 `ToolMetadata` 字段，`think_augment` 和 `defer` 提供交互式开关
- **Permissions**：权限评估结果，显示适用的规则和决策
- **覆写**：编辑工具的描述、`ToolTag` 与自定义标签

覆写会安装该工具的一份编辑副本，并保留被替换的定义，因此 **恢复原始定义**
可以放回来源自身的定义。注册表沿用同一个键与同一个可调用对象，所以调用、日志与权限
行为完全不变；只有对外展示的元数据发生变化。被覆写的工具会在弹窗中标记，
`GET /api/overrides` 会列出每个覆写及其当前和原始定义。

## 命名空间管理

- 一键启用/禁用命名空间中的所有工具
- 为命名空间中的所有工具切换 `think_augment` 和 `defer`
- 查看每个命名空间的工具数量
- 查看启用/禁用分布

## 执行日志查看器

- 按工具名称或状态过滤日志（成功、错误、超时、拒绝）
- 在工具过滤框中按回车或点击“应用”执行查询
- 展开条目可查看参数、结果、警告；失败时还会显示异常类型和可折叠的调用栈
- 过滤条件在面板自身的刷新和启用/禁用操作后保持有效（整页重新加载会重置）
- 需要时清除日志（会要求确认）
- 查看聚合统计（包含超时）

## 状态导入/导出

- 将当前禁用状态导出为 JSON
- 导入之前导出的状态
- 无效文件会在确认弹窗之前被拒绝；服务端收到格式错误的请求会返回 `400`，且不会改动当前的禁用集合
- 名称必须能解析到已注册工具或命名空间；未知名称返回 `400`，而不是悄悄清空禁用集合
- 适用于备份/恢复场景

## 注册表设置

状态面板还控制命名空间分隔符（`-` 或 `.`）。应用更改会**立即重命名所有带命名空间的工具**——例如 `math_utils-square` 变为 `math_utils.square`。仍使用旧名称的调用将无法解析，已有日志条目保留旧名称。UI 会在应用前要求确认，并在之后刷新所有标签页。

## 语言切换（i18n）

Web UI 支持英文和中文。语言切换下拉框位于页面右上角的标题栏中。

- 选择 **EN** 切换为英文，选择 **中文** 切换为中文
- 语言偏好通过 `localStorage` 持久化，下次访问时自动恢复
- 所有 UI 元素即时更新——标签页、表头、按钮、过滤器、提示消息、弹窗对话框和空状态
- 切换语言时，动态内容（工具列表、日志条目、统计数据）会以所选语言重新渲染
